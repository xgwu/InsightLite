# InsightLite 种子用户文档（内部试点 v1 · W10）

> 对象：首批试点用户（HRBP / 部门经理 / 员工 / 审计）。读完这一页即可开始用。
> 系统当前只读：所有查询都是「问数」，不会修改任何数据。

## 1. 登录

试点期使用 mock SSO（`POST /dev/login`，按演示身份签发令牌）：

| SSO 身份 | 对应系统角色 | 能看到什么（一句话） |
|---|---|---|
| `employee` | employee | 只能看自己的数据；部门统计只出数字，无个人明细 |
| `manager` | dept_manager | 本部门（含子部门）全员；**薪资列永远脱敏** |
| `hrbp` | hr_admin（豁免+逐次审计） | 全员全字段；每次查询记入审计日志 |
| `exec` | hr_admin（豁免+逐次审计） | 同上 |
| `auditor` | auditor | 只能看纯 public 统计口径；碰任何敏感字段整查询拒绝 |

令牌有效期满后重新登录即可；任何篡改/过期令牌一律 401，不存在降级放行。

## 2. 怎么问数

聊天框直接用自然语言提问，例如：

- 「本月各部门迟到人次排名」
- 「技术部上个月平均净薪资」（manager 只会看到自己部门；hrbp 看全员）
- 「6 月考勤异常前三名的员工明细」（员工问他人明细 → 明确拒绝，这是设计行为）

六种结果状态：

| 状态 | 含义 | 你该做什么 |
|---|---|---|
| answered | 已作答 | 直接看结果/图表 |
| clarified | 需要澄清 | 从给出的选项里补一句话再问 |
| refused_scope | 超出数据范围 | 换一个在数据范围内的问法 |
| denied | 权限不足 | 显示原因；不要反复重试，需要权限找 HRIS 管理员 |
| error | 系统异常 | 截图反馈给 HRIS 管理员 |
| （脱敏） | 看到了但数值被遮蔽 | 该列对你的角色不可见，属正常 |

提示：问「排名/Top N」时同时说明时间范围和部门范围，命中率最高。

## 3. 看板

- 对话结果点「加入看板」→ 填标题 → 入板（FR-27：入板时会做一次人工比对确认）。
- **看板只存口径不存数据**：每次打开都按你本人的权限重新执行。所以同一张看板，
  HRBP 看到 9 个部门，经理只看到本部门子树——这不是 bug，是权限设计（FR-33）。
- 看板支持拖拽布局（自动保存）与点卡片回跳对话继续下钻。

## 4. 你的权限怎么被保护（给非技术同事的一段话）

每条查询先过「权限策略引擎」再碰数据库：该拒的先拒（不触库）、该遮的编译期就置空、
该收窄的行级条件由引擎注入而不是应用代码过滤。管理员查看全员薪资属于「豁免」，
但**每一次都留痕**：谁、何时、查了什么口径、模型版本——审计可查、不可改。

## 5. 常见问题

- **为什么我查的数字和同事不一样？** 权限范围不同（行级收窄）。口径相同、范围不同。
- **为什么薪资显示「—」？** 列级脱敏对你是 MASK。需要权限走正式审批，不要在对话里绕。
- **能导出数据吗？** 试点期不提供导出（一期只读）。
- **发现数字明显不对？** 把问题原文 + 返回的 SMQ/SQL（结果卡片里可展开）发给 HRIS 管理员。

## 6. 反馈闭环（W11–W12 日报机制）

试点的三项核心指标：口径一致率 / 静默错误率 / 明确失败率。
你的每次纠正都会变成一条 eval 固定用例——纠错即沉淀，越用越准。
反馈渠道：试点群 @HRIS管理员，或直接在对话里指出错误后截图。
